# Typography

Typography defines reading rhythm and hierarchy for FeitozaUI. It should make technical interfaces feel precise and readable before it expresses brand personality.

This is not a full text component system yet. Dedicated `Text` or `Heading` components may be added later after the foundation is stable.

## Responsibilities

| Role | Token | Responsibility |
| --- | --- | --- |
| Interface | `typography.roles.interface` | Controls, labels, body copy, documentation, and repeated reading. |
| Reading | `typography.roles.reading` | Longer copy and prose-like documentation. |
| Heading | `typography.roles.heading` | Current heading compatibility role. |
| Display | `typography.roles.display` | Expressive titles and identity moments. |
| Brand | `typography.roles.brand` | Controlled brand emphasis. |
| Code | `typography.roles.code` | Code, commands, identifiers, endpoints, and logs. |
| Data | `typography.roles.data` | Metrics, IDs, timestamps, versions, and technical metadata. |

Inter remains the default family for interface and reading. Space Grotesk owns display and brand expression. JetBrains Mono owns code and data. Outfit remains as a compatibility heading role and should not be expanded for new identity work.

## Usage Notes

- Use Inter roles for controls, labels, body copy, and documentation.
- Use Space Grotesk roles only for display, brand, and deliberate identity moments.
- Use JetBrains Mono roles for code, identifiers, metrics, logs, timestamps, and technical metadata.
- Keep Outfit as heading compatibility for now; do not add new responsibilities to it.
- Avoid introducing new font families in component code.
- Treat full text components and font-loading changes as future work.
- Do not use typography as cyberpunk decoration. Legibility comes first.
