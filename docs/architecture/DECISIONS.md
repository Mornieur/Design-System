# Architecture Decisions

This directory uses Architecture Decision Records (ADRs) to document important project choices.

ADRs should be used when a decision affects architecture, scope, maintainability, package design, public API, or long-term direction.

## ADR Format

Each ADR should include:

- Status
- Context
- Decision
- Consequences

## Status Values

- Proposed: the decision is being discussed.
- Accepted: the decision guides current work.
- Superseded: a newer ADR replaces it.
