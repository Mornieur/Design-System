# Maintenance

FeitozaUI should be maintained as a long-term platform, even while it remains a portfolio project.

## Bug Fixes

Bug fixes should include a test when the behavior can be reproduced automatically.

## Deprecations

Deprecated APIs should be documented before removal when possible. Deprecation should include a recommended replacement.

## Breaking Changes

Breaking changes should be grouped, documented, and released only when versioning is active.

## Migration Guides

Migration guides should include before and after examples for public API changes.

## Version Support

Before publishing, version support is informal. After publishing, supported versions should be documented.

## Ownership

The maintainer owns API consistency, documentation quality, accessibility expectations, and release decisions.

## Review Process

Reviews should check scope, API design, accessibility, tests, docs, and whether the change belongs in the core library or the showcase.
