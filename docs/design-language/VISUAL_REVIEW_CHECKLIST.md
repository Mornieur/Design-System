# Visual Review Checklist

Use this checklist before approving any documentation UI change.

## Identity

- Does the screen look like documentation for a React library?
- Is the FeitozaUI personality visible without turning into a dashboard?
- Is the interface closer to the approved Figma than before?
- Did the change make the experience simpler?

## Hierarchy

- Is the content understood within three seconds?
- Is the primary heading clearly dominant?
- Is the first example the protagonist when the page is example-driven?
- Are preview, code, and API sections easy to distinguish?

## Noise

- Are there removable boxes?
- Is there decorative technical text with no user value?
- Is any fake information present?
- Is the grid texture too visible?

## Navigation

- Does the sidebar help navigation instead of competing with reading?
- Are route groups real and predictable?
- Is mobile navigation simple and focused?
- Are utilities separated from primary navigation?

## Theme Quality

- Is dark mode readable and intentional?
- Is light mode intentional rather than an inverted dark mode?
- Do cyan and coral stay restrained?
- Are contrast and focus states preserved in both themes?

## Accessibility

- Does keyboard navigation work?
- Is the focus order sensible?
- Does the screen remain understandable at 200% zoom?
- Does reduced motion remain respected?
- Are buttons, links, and headings understandable?

## Mobile

- Does the screen keep its editorial focus on mobile?
- Are nested surfaces reduced appropriately?
- Is there any clipping, overlap, or overflow?

## Final Decision

- Classify any remaining issue as `blocker`, `important`, or `refinement`.
- Do not approve if a blocker remains unresolved.
